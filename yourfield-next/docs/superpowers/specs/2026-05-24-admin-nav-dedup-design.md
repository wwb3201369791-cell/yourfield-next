# 后台侧边导航 "父子重名堆叠" 优化书

- 文档日期: 2026-05-24
- 影响范围: Payload Admin 左侧导航
- 改动量评估: 3 个文件、各删 1 行 (合计 -3 行)
- 风险: 极低 (仅影响后台导航分组渲染, 不涉及数据/权限/路由)

---

## 1. 现状与问题

Payload 后台左侧导航当前呈现为:

```
咨询表单            ← group 标题
  咨询表单          ← collection 本体
产品管理            ← group 标题
  产品大类
  产品
解决方案            ← group 标题
  解决方案          ← collection 本体
新闻动态            ← group 标题
  新闻动态          ← collection 本体
联系方式            ← (Globals / 站点设置, 非本次改动)
  联系方式
```

观感问题: 凡是 group 名称与组内唯一 collection 名称相同的, 都会出现 "组名 + 本体" 的双行同名堆叠, 视觉上像是重复了一份, 用户每次都要扫两行才能找到入口。

### 根因

每个 collection 都通过 `admin.group` 声明了所属分组, 但其中:

| group       | 成员数量 | collection             | 是否真分组 |
| ----------- | -------- | ---------------------- | ---------- |
| 咨询表单    | 1        | FormSubmissions        | ❌ 假分组  |
| 产品管理    | 3        | ProductGroups/Categories/Products | ✅ |
| 解决方案    | 1        | Solutions              | ❌ 假分组  |
| 新闻动态    | 1        | News                   | ❌ 假分组  |
| 内容管理    | 3        | FAQs/Media/Pages       | ✅         |
| 运营管理    | 1        | SearchLogs             | ❌ 假分组  |
| 系统设置    | 3        | AuditLogs/Roles/Users  | ✅         |

Payload 的规则: 只要声明了 `admin.group`, 哪怕组里只有 1 个 collection, 也会画出一行 group 标题。这就是"重复堆叠"的来源。

---

## 2. 优化目标

1. 消除 "组名 + 本体" 同名行的视觉堆叠。
2. 不改动任何业务字段、权限、URL, 现有书签/培训资料不失效。
3. 不引入新组件、不接管 Payload 默认侧栏, 升级 Payload 时零摩擦。

非目标 (本次不做):

- 不重新规划信息架构 (那是方案 B 的事)。
- 不做自定义侧栏 UI (那是方案 C 的事)。
- 不处理 Globals (联系方式/导航/站点设置) 的展现, 它们走的是另一套 nav 段, 与本问题无关。

---

## 3. 改动方案 (方案 A)

**核心动作**: 把"单成员 group"的 `admin.group` 字段删掉, 让它们升级为顶层导航项。多成员 group 一律保留。

### 3.1 文件级改动清单

| 文件 | 当前 | 改后 |
| ---- | ---- | ---- |
| `src/collections/FormSubmissions.ts:51` | `group: '咨询表单',` | 删除该行 |
| `src/collections/Solutions.ts:24`       | `group: '解决方案',` | 删除该行 |
| `src/collections/News.ts:19`            | `group: '新闻动态',` | 删除该行 |

`SearchLogs.ts` 的 `group: '运营管理'` 虽然也是单成员, **本次不动**: "运营管理"与"搜索日志"不同名, 不构成堆叠观感, 留着它能为后续可能加入的运营类 collection (如行为日志、转化漏斗) 留好分组占位。

### 3.2 改动后预期效果

```
咨询表单                 ← 顶层 (原 FormSubmissions, 升一级)
产品管理
  产品大类
  产品
解决方案                 ← 顶层 (原 Solutions, 升一级)
新闻动态                 ← 顶层 (原 News, 升一级)
内容管理
  常见问题
  媒体资源
  页面
运营管理
  搜索日志
系统设置
  审计日志
  角色
  用户
```

视觉密度下降, 同名双行消失。

### 3.3 顺序考量

Payload 默认会按 `collections` 数组顺序在每个 group 内排列, 顶层项之间也是按数组顺序。当前 `payload.config.ts:235-249` 的顺序为:

```
FormSubmissions, ProductGroups, ProductCategories, Products,
Solutions, News, Pages, FAQs, Media, SearchLogs, Users, Roles, AuditLogs
```

按此顺序渲染, 顶层导航将依次为: **咨询表单 → 产品管理 → 解决方案 → 新闻动态 → 内容管理 → 运营管理 → 系统设置**, 与你截图里的视觉顺序一致, 不需要额外调整数组。

## 5. 回滚方案

如果改后发现某顶层项过多需要重新归组, 只需在对应 collection 的 `admin` 块里加回一行:

```ts
admin: {
  // ...
  group: '你想要的分组名',
}
```

无需迁移、无需改数据库, git 一次 revert 即可全量回退。

---

## 6. 后续可选演进 (非本次)

- **方案 B (信息架构重组)**: 如果后续 collection 数量继续增长, 重新规划成 4 大组 (营销内容 / 产品 / 线索 / 系统), 让每组都有 2-4 个成员, 避免再次出现"假分组"。
- **方案 C (自定义侧栏)**: 想要图标 + 卡片高亮 + 折叠记忆等定制化体验, 通过 `admin.components.beforeNavLinks` 或完全替换 Nav 组件实现, 工作量大, 不建议现阶段做。
